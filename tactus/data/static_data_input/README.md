# The reference data manager tool

## Introduction

The *reference data manager* tool manage the static data files on different `<platforms>`.

The general principle is to maintain and exploit two json files for each `<platform>` :
- *reference list*: a reference list of expected files
- *file index*: a file index containing the list of the actual files on disk

The following commands to manage the static data of the different `<platforms>`:

- `copy <platform_1> <platform_2>`: copy from <platform_1> the list of files actually missing on <platform_2>
- `build_ref <platform>`: build the *reference list* for `<platform>`, based on a pre-defined list of files
- `status <platform>`: build *file index* and compare it to *reference* list, for `<platform>`.
- `show <platform>`: list the content of the *reference list* for `<platform>`
- `diff <platform_1> <platform_2>`: compare the *reference list* of <platform_1> and <platform_2>
- `read_logs <platform>`: extract a flat list of files from the log files of a set of Tactus experiments

The implementation of these commands is relying different operations performed on these *reference_list* and *file index* files.
More details are provided for the different commands in the next sections. 

### Configuration 

The location of the different files and all the required information for a `<platform>` is stored in the config files `data/config.json`, containing for each `<platform>`:
- `current_index_json`: name of the *file index* file in json format (default: `data/platform/<platform>/current_index.json`)
- `reference_json`: name of file the *reference list* in json format (default: `data/platform/<platform>/reference.json`)
- `root_folder`: folder containing reference files (on atos:`/ec/project/accord/tactus`)
- `log_folder` : folder containing the log of experiments (on atos: `$SCRATCH/tactus`)
- `ignore`: list of files containing the list of files and folder to ignore in `root_folder` (see below)
- `output_file_from_log`: the name of the file that will be generated by the read_logs command
- `input`: list of input files for `build_ref` command

### ignored folder and files

Some commands required to walk all the files in the reference folder. This operation can be costly if the folder contains a lot of entries. 

Similar to the `.gitignore` file used in `git`, a list of files and folders to skip during the indexing process is provided in the `platform/<platform>/ignore` file.


## Description of the commands


### 1. `copy` to transfer missing files between `<platforms>`

#### Description 

- The `copy` command will copy from `<platform_1>` the list files actually missing on `<platform_2>`.

- Usage: must be executed from `<platform_1>`.


#### Syntax 

```
$ python reference_data_manager.py build_ref <platform_1> <platform_2> 
```
- Argument:
    - `<platform_1>`: the source machine, from which the files will be copied
    - `<platform_2>`: the target machine, to which only the missing files will be copied
- Result:
    - display a list of commands to copy the files

#### Example


Copy from atos to lumi the list of files actually missing on lumi:

```
$ python reference_data_manager.py build_ref atos lumi 
```
In this example, the command is launched from atos (the source machine).

#### Technicalties

The list of missing files on `<platform_2>` is computed by comparing the `reference.json` and `current_index.json` of `<platform_2>`. The list of files are then retrieved using the `root_folder` of `<platform_1>`.


### 2. build_ref to generate *reference list* of `<platform>`


#### Description 

- The `build_ref` command will generate the *reference list* from predifined lists of files. 
The predefined lists of file are listed in the configuration file in the `input` key.
For instance, a list of files generated from the log files of experiments will be used as `input`.

- Usage: can be executed from any platform, to build the *reference list* of any other platform.

#### Syntax 

```
$ python reference_data_manager.py build_ref <platform> 
```
- Argument:
    - `<platform>`: the machine for which the *reference list* will be generated
- Result:
    - generate `reference.json` of the platform 

#### Example

Generation of the *reference list* for atos:

```
$ python reference_data_manager.py build_ref atos
```

### 3. `status` to display the status of a `<platform>`


#### Description 

- The `status` command will display a list of files already present or still missing on a given `<platform>`, in a similar way as the `git status` command.
More specifically, the command:
  - re-builds the *file index* of the `<platform>` and store it as `current_file_index.json`
  - performs a two-side comparison between `current_file_index.json` and `reference_list`, the *reference list* of the platform.

- usage: can be executed from any `<launch platform>` to get the status of any other `<platform>`. However, the index is only rebuilt when the command is `<launch platform` is equal to the `<platform>`. Otherwise, the *file index* can't be reuilt: the rebuilt step is skipped and the existing `current_file_index.json` is used for comparison.

#### Syntax 

```
$ python reference_data_manager.py status <platform> --long --verbose
```
- Arguments:
    - `<platform>`: the machine you are requesting a status
    - `--long` (optional): provide more comprehensive results
    - `--verbose` (optional): provide more debugging information.
- Result:
    - display the status of the platform, in a similar way as `git status`
    - generate `current_file_index.json` of the platform (when possible)

#### Examples

- status of ATOS from this machine: rebuild *file index* and give status

```
$ python reference_data_manager.py status atos
Comparing ./data/platform/atos/reference.json and /ec/project/accord/tactus
Rebuilding index for /ec/project/accord/tactus...
# Common files in ./data/platform/atos/reference.json and /ec/project/accord/tactus: 182
# No files only in ./data/platform/atos/reference.json
# Files only in /ec/project/accord/tactus: 1403
# No file with incorrect size
Hint: use --long to get more detail
```

- status of ATOS from laptop: give status using old *file index*

```
 $ python reference_data_manager.py status atos
Comparing ./data/platform/atos/reference.json and /ec/project/accord/tactus
WARNING - Index could not be rebuild, /ec/project/accord/tactus not found
          Using previous index which might be outdated
# Common files in ./data/platform/atos/reference.json and /ec/project/accord/tactus: 182
# No files only in ./data/platform/atos/reference.json
# Files only in /ec/project/accord/tactus: 1403
# No file with incorrect size
Hint: use --long to get more detail
```


### 4. `show` to list content of *reference list* of a `<platform>`

#### Description 


- The `show` command will display the list of files from the *reference list* of `<platform>`

- Usage: can be executed from any platform to show the content of the *reference list* of any other platform.

#### Syntax 

```
$ python reference_data_manager.py show <platform>
```
- Argument:
    - `<platform>`: the machine for which the list of files of *reference list* will be displayed
- Result:
    - display the list of files contained in *reference list*

#### Example

List the files in *reference list* for atos:

```
$ python reference_data_manager.py show atos
```


###  5. `diff` to list the differences between the *reference lists* of two `<platforms>`

#### Description 

- The `diff` command will compare the *reference list* of the two input <platform_1> and <platform_2>, in a similar way as the `diff` command.

- usage: can be executed from any platform, to display the difference between any two other platforms


#### Syntax 

```
$ python reference_data_manager.py diff <platform_1> <platform_2>
```
- Arguments:
    - `<platform_1>`: the first machine 
    - `<platform_1>`: the second machine 
- Result:
    - display the difference between the *reference list* in a similar way as the `diff` command.

#### Example

Compare the *reference lists* of atos and lumi:

```
$ python reference_data_manager.py diff atos lumi
```

#### Technicalities

The command will compare the `reference_list.json` files of the two platforms and display a formatted results.


### 6. `read_logs` to extract list of required files from experiment logs


#### Description 

- The `read_logs` command will extract a flat list of files from the log files of a set of Tactus experiments.
The results is written as a flat list of files in the result file.

- usage: must be executed from `<platform>`


#### Syntax 

```
$ python reference_data_manager.py read_logs <platform>
```
- Argument:
    - `<platform>`: the machine for which the list of files will be extracted
- Result:
    - generate the file `from_test_runner_log.txt`, containing the list of files parsed from the logs of `log_folder`


The name of the `log_folder` and the name of the `output file` is provided in the config file, under the
keys `log_folder` and the `output_file_from_log` of the `<platform>`.


#### Example

Extract the list of files from the log of experiments in `"$SCRATCH/tactus"` and store the results in the file `data/cycles/cy50t2/from_test_runner_log.txt`

```
$ python reference_data_manager.py read_logs atos
```

The name of the folder `"$SCRATCH/tactus"` and the name of the output file `data/cycles/cy50t2/from_test_runner_log.txt` are defined in the config_file for atos.


#### Technicalities

The command parse all the files present in the `log_folder` of the `<platform>`, and store the results in its `output_file_from_log` file. The parsing itself is performed by the bash script `files_list_from_log_folder.sh`, using a combination of `find`, `sed` and `grep` commands for maximum efficiency.
